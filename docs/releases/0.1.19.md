# BetterComms 0.1.19

This patch release includes the mobile layout fixes and adaptive native glasses video sender from 0.1.18, plus two call resize fixes found during late combined-code review. All packages are built from the same release commit using Wails v3. Native media remains experimental; the 720×1280 at 30 fps setting is a capture target, not a guaranteed delivery rate.

## Downloads

- Windows x64: download the `windows-x64-setup.exe` installer. It is unsigned and requires Microsoft WebView2 Evergreen.
- macOS Apple Silicon: download the `macos-arm64.dmg`.
- macOS Intel: download the `macos-x64.dmg`.
- iPhone/iPad: download the experimental `ios-arm64-adhoc.ipa`. It targets iOS 17.2+ and must be re-signed with your Apple certificate and a matching provisioning profile before installation. This is an ad hoc cryptographic signature, not an Apple Ad Hoc distribution profile or a TestFlight build. Preserve the Wi-Fi Information and Hotspot Configuration entitlements needed by Meta camera transport.
- `SHA256SUMS.txt` contains the package checksums.

macOS requires version 15 or later. Drag BetterComms into Applications. These apps are ad hoc signed, not notarized or signed with Developer ID; use System Settings → Privacy & Security → Open Anyway if macOS blocks them. Each Mac download is a single DMG, without an extra nested ZIP.

## Changes

- Active Windows camera overlays survive switching to the compact call layout when the window narrows. More can show or hide the overlay in compact windows; leaving the call still closes it.
- Direct-call chat defaults follow screen resizing until you choose to open or close chat; explicit choices remain intact.

- Phones use bottom navigation and conversation drawers, with cameras filling the available call stage in portrait and landscape.
- Six 44 px call controls fit at 320 px. Camera source selection, recording and layout actions live in More, while call status has a separate row.
- Direct-call chat has a Back to call action; touch messages reveal actions; screen focus can be cleared without stopping watched media. Camera docking and Reset layout remain available on phones. Unsupported fullscreen actions stay hidden.
- Native iPhone glasses video retains its 720×1280/30 fps target. H.264 starts at 3 Mbps and adapts between 1 and 8 Mbps using fresh receiver loss and bitrate feedback. The most constrained viewer limits the shared encoder.
- Receiver recovery requests produce native keyframes without restarting the glasses session. Sustained queue delay catches up at a fresh keyframe, and rejected bitrate updates keep capture running.
- Release workflow actions are pinned to commit hashes, and the Windows pacing test measures its cadence after frame setup.

## Limits

Glasses connection repeatability, real remote 720×1280/30 fps delivery, and background/locked-phone video remain unverified. iOS sharing does not capture other apps or continue as a full-phone broadcast. macOS does not provide Windows process capture or application audio. Linux has no published native package. iOS microphone effects and voice balancing are bypassed on its direct microphone path. Packaged authentication and native media still require the platform/device acceptance gates documented in `docs/WAILS_COMPLETION.md`, `docs/IOS_EXPERIMENT.md`, and `docs/NATIVE_MEDIA_BOUNDARY.md`.

The hosted client is available at https://app.bettrcomms.com. TURN deployment and cross-network acceptance remain outstanding. Recordings and rewind retain the limitations in `docs/RELEASE_NOTES.md`.
